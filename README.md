# 한글 모아모아 수읽기

메이플스토리 한글날 미니게임 「한글 모아모아」(2026.10.01 ~ 10.14)용 수읽기 도구입니다. 현재 게임판과 손패 3개를 입력하면, 어느 조각을 어느 칸에 어떤 순서로 둘지 추천합니다.

- `index.html` 하나로 동작합니다. 브라우저로 열면 되고, 서버나 설치가 필요 없습니다.
- 학습된 판 평가 표(약 3MB)가 페이지 안에 들어 있습니다.
- 계산은 모두 브라우저의 웹 워커에서 돌아갑니다.

## 1. 사용법

1. **판 입력**: "칸 칠하기" 모드에서 칸을 누르거나 끌어서 실제 게임판을 옮겨 적습니다. 능력 아이콘이 있으면 "점찍기 아이콘" / "바꿔뽑기 아이콘" 모드로 위치를 찍습니다(최대 3개, 초과 시 오래된 것부터 사라짐).
2. **손패 지정**: 슬롯(1~3번)을 고른 뒤 아래 조각 목록에서 게임에 나온 조각을 누릅니다. 지정하면 다음 빈 슬롯으로 자동 이동합니다.
3. **상태 입력**: 점수, 제거한 줄(단계 판정용), 다음 능력까지 남은 배치 수, 점찍기·바꿔뽑기 보유 개수를 입력합니다.
4. **추천 보기**: 입력이 바뀌면 0.3초 뒤 자동으로 계산이 시작됩니다. "AI 추천 순위"에서 후보를 누르면 판에 수순 번호가 표시됩니다.
   - 점선 테두리 줄과 취소선 행 번호: 수순 중 지워지는 줄
   - 사선으로 나뉜 칸: 줄이 지워진 뒤 다른 조각이 다시 채우는 칸
   - "다음 수 ▶"로 넘기면 한 수씩 그 수를 두기 직전 판을 보여 주고, 이미 둔 수는 흐린 번호로 남깁니다.
5. **반영**: "이 수순대로 두기"를 누르면 판, 점수, 줄 수, 능력 카운트가 갱신됩니다. 7번째 배치 뒤에는 능력 아이콘 입력 모드로 자동 전환되니 실제 화면을 보고 위치를 찍습니다.
6. 직접 두고 싶으면 "조각 놓기" 모드에서 판을 누릅니다(우클릭은 회전). 잘못 입력하면 "되돌리기"(최대 200단계).

## 2. 게임 규칙 정리

공식 공지(테스트월드 1.2.206 업데이트, 2026.09.10)에서 확인해 엔진에 반영한 규칙입니다.

| 항목 | 내용 |
|---|---|
| 판 | 가로 10칸 × 세로 16칸 |
| 조각 | 자음·모음 모양 19종. 90° 회전과 좌우 반전 가능 |
| 손패 | 3개씩 지급, 3개를 모두 놓아야 다음 3개 지급 |
| 줄 제거 | 가로 한 줄이 꽉 차면 제거. 세로로 꽉 차도 제거되지 않음 |
| 배치 점수 | 놓은 조각의 칸수 |
| 줄 제거 점수 | 동시 제거 n줄당 300 × n² (1줄 300 · 2줄 1,200 · 3줄 2,700 · 4줄 4,800 · 5줄 7,500) |
| 능력 아이콘 | 조각 7회 배치마다 빈 칸에 생성(점찍기 40% / 바꿔뽑기 60%). 판 위 최대 3개 |
| 능력 획득 | 아이콘이 있는 줄을 지우면 획득 + 50점. 보유 합계 최대 7개, 최대치일 때는 획득 안 되고 아이콘이 남음 |
| 점찍기 | 원하는 빈 칸 1칸 채우기. 7회 배치 카운트에 포함되지 않음 |
| 바꿔뽑기 | 손패 조각 하나를 다시 뽑기(정해진 확률) |
| 단계 | 누적 제거 줄 0~30 / 31~60 / 61~100 / 101~150 / 151 이상. 단계가 오를수록 칸수가 적은 조각이 덜 나옴 |
| 게임 종료 | 회전·반전을 포함해 놓을 자리가 없고 쓸 능력도 없을 때 |
| 상한 | 한 판 최대 500,000점 |

### 확인되지 않아 가정한 부분

- **줄 제거 후 위쪽 줄 이동**: 공지에 명시가 없습니다. 같은 게임을 분석한 공개 프로젝트([cbh456746/mopago](https://github.com/cbh456746/mopago))의 정리에 따라 "내려오지 않음"을 기본값으로 했습니다. 페이지의 계산 설정에서 "아래로 내려옴"으로 바꿀 수 있습니다.
- **조각 등장 확률**: 공식 수치가 없습니다. 위 공개 프로젝트가 공개한 가정을 따랐습니다.
  - 조각 i의 가중치 = r^((10 − 칸수)/9), r = 0.6^(단계−1)/4
  - 1단계는 19종 균등(각 5.26%)입니다.
  - 5단계에서는 1칸 조각의 가중치가 10칸 조각의 0.6배가 됩니다.
  - 그 결과 4칸 이하 조각의 합산 확률이 1단계 36.84% → 5단계 31.34%로 줄어듭니다.
  - 비율(0.6)은 페이지 설정에서 바꿀 수 있습니다.

## 3. 시스템 구성


## 4. 게임 엔진 (`core.js`)

- **판 표현**: 16개 행 각각을 10비트 정수로 저장합니다(1 = 채워짐, 꽉 찬 줄 = 1023).
  - 충돌 검사: 조각 행 마스크를 왼쪽으로 밀어 비트 AND
  - 줄 완성 검사: `row === 1023`
- **조각 변형**: 기본 모양에서 회전 4 × 반전 2 = 8가지를 만들고 중복을 제거해 미리 계산합니다. UI의 회전/반전 버튼은 이 8가지 방향 표(`orient`)로 연결됩니다.
- **줄 제거**: 꽉 찬 줄을 비우고 다음 처리를 합니다.
  - 아이콘이 있던 줄이면 능력을 획득합니다(보유 7개 미만일 때만).
  - 중력 옵션이 켜져 있으면 위 줄과 아이콘을 아래로 당깁니다.
- **능력 아이콘 생성(시뮬레이션용)**: 7회 배치마다 빈 칸 중 하나를 균등 무작위로 고르고, 40%/60% 확률로 종류를 정합니다. 아이콘이 이미 3개면 가장 오래된 것을 지웁니다.
- **막혔을 때 처리(`rescue`)**: 시뮬레이션에서 손패를 다 놓을 수 없을 때 아래 순서로 시도합니다.
  1. 놓을 수 없는 조각을 바꿔뽑기로 교체
  2. 가장 많이 찬 줄에 점찍기
  3. 아무 조각이나 바꿔뽑기
  4. 셋 다 안 되면 게임 종료
- **난수**: 시드 고정 난수 생성기(mulberry32)를 써서 벤치마크를 같은 시드로 재현할 수 있습니다.

## 5. 평가 함수

판이 "앞으로 얼마나 점수를 더 낼 수 있는 상태인가"를 숫자로 매기는 부분입니다. 두 층으로 되어 있습니다.

### 5-1. 손으로 설계한 평가식 (18항목)

| 항목 | 의미 | 학습된 가중치 |
|---|---|---|
| `holes` | 상하좌우가 모두 막힌 빈 칸 | −62.9 |
| `segs` | 각 줄의 빈 구간 개수(조각이 들어갈 덩어리 수) | −98.1 |
| `rowTrans` | 가로 방향 채움/빔 전환 횟수 | −1.9 |
| `colTrans` | 세로 방향 채움/빔 전환 횟수 | −9.0 |
| `fill2` | 줄별 채운 칸수의 제곱합(줄을 몰아서 채울수록 큼) | +3.9 |
| `near` | 8칸 이상 찬 줄 수 | +0.1 |
| `emptyRows` | 완전히 빈 줄 수 | +19.4 |
| `filled` | 전체 채운 칸 수 | +7.3 |
| `space3` | 3×3 빈 공간 개수(큰 조각 자리) | −3.5 |
| `icon` | 능력 아이콘이 있는 줄의 채움 정도 | +16.3 |
| `dot` | 점찍기 보유 개수 | +641.0 |
| `reroll` | 바꿔뽑기 보유 개수 | +222.3 |
| `fitP` | 지금 판에 놓을 수 있는 조각들의 등장 확률 합 | +138.9 |
| `fitMiss` | 놓을 자리가 아예 없는 조각 종류 수 | −20.7 |
| `deep` | 좌우가 막힌 폭 1칸 세로 우물 | +11.3 |
| `combo` | 같은 칸이 빈 9칸 줄이 연속으로 쌓인 정도(한 번에 여러 줄 제거 준비) | +7.8 |
| `fitCnt` | 조각별 배치 가능 위치 수(최대 8, 확률 가중) | +656.5 |
| `minFit` | 가장 빡빡한 조각의 배치 가능 위치 수 | +3.8 |

가중치는 판 끝까지 두는 자가대국으로 최적화했습니다(7장). 학습 결과 보유 능력과 "모든 조각이 놓일 자리가 넉넉한가(`fitCnt`)"의 비중이 가장 크게 잡혔습니다.

### 5-2. 판 모양 패턴표 가치 함수 (`ntv2.js`)

2048 AI에서 쓰는 n-tuple 방식입니다. 판의 국소 모양마다 학습된 점수를 표에서 찾아 모두 더합니다.

| 표 | 보는 범위 | 항목 수 | 판 한 장당 조회 |
|---|---|---|---|
| 행 쌍 | 붙은 두 줄 전체(위·아래 벽 포함, 좌우 대칭 4배 증강) | 1,048,576 | 68 |
| 3×4 창 | 세로 3 × 가로 4 | 4,096 | 98 |
| 4×3 창 | 세로 4 × 가로 3 | 4,096 | 104 |
| 4×4 창 | 세로 4 × 가로 4 | 65,536 | 91 |
| 2×5 창 | 세로 2 × 가로 5 | 1,024 | 90 |
| 5×2 창 | 세로 5 × 가로 2 | 1,024 | 108 |

최종 가치 = L0 + Σ(표 값) + 1 × 평가식(5-1). 단위는 100점이며, 평가식은 패턴표가 못 보는 판 전체 정보(배치 가능성, 능력 보유)를 보완합니다.

## 6. 수 추천 알고리즘

### 6-1. 후보 수순 탐색 (빔 탐색)

- 손패 3개를 놓는 **순서와 위치를 함께** 탐색합니다. 깊이 1 → 2 → 3을 넓혀 가며 각 깊이에서 상위 B개(기본 24)만 남깁니다.
- 각 단계에서 줄 제거, 점수, 아이콘 획득을 실제로 계산합니다.
- 단계 사이에 **점찍기 사용**(9칸 찬 줄을 완성하는 경우)도 후보로 넣습니다. 한 수순에 최대 2회까지입니다.
- 중간 깊이에서는 비용이 싼 평가(패턴표 + 평가식 중 빠른 항목)를 쓰고, 마지막에만 배치 가능성 항목까지 포함한 전체 평가를 씁니다.
- 같은 결과 판에 도달하는 수순은 하나만 남깁니다.
- **다양한 후보 확보**: 상위 수순이 모두 같은 첫 수로 몰리지 않도록 아래처럼 고릅니다.
  1. 첫 수 후보를 넓게 뽑습니다.
  2. 첫 수마다 나머지 두 수를 다시 탐색합니다.
  3. 첫 수와 결과 판이 서로 다른 상위 8개를 추천 후보로 둡니다.
- 손패를 다 놓을 수 없으면 "N개 중 M개만 놓을 수 있습니다" 경고를 띄웁니다.

### 6-2. 몬테카를로 롤아웃 (순위 결정)

- 후보 8개를 돌아가며, 수순을 둔 뒤 **무작위 미래 조각**(단계별 확률)과 **무작위 능력 아이콘**으로 설정한 깊이(기본 8손 = 24조각)만큼 실제로 끝까지 둡니다.
- 롤아웃 중의 수는 빠른 정책(빔 폭 2 + 같은 가치 함수)으로 고릅니다.
- 후보의 점수는 롤아웃 동안 얻은 점수의 평균입니다. 도중에 게임이 끝나면 −3,000점을 줍니다.
- 표시 항목:
  - 평균 점수
  - 95% 신뢰구간(±1.96 × 표준오차)
  - 시뮬레이션 판 수
  - 생존율(90% 초과 초록, 70% 초과 노랑, 그 아래 빨강)
- 기본 10초 동안 돕니다. 스레드 수는 (CPU 코어 − 1)이고, "시뮬레이션 계속"을 누르면 기존 통계에 이어서 더 돌립니다.

### 6-3. 바꿔뽑기 판단

바꿔뽑기를 보유하면 슬롯마다 기대값을 계산합니다.
- 계산 방식: 19종이 나올 확률 × 그 조각으로 바꿨을 때의 최선 수순 평가값
- 판단: 가장 나은 슬롯의 기대 이득이 120점을 넘거나 손패를 다 놓을 수 없는 상황이면 "바꿔뽑기 권장: N번 슬롯"을 띄우고, 아니면 "아끼는 편이 낫습니다"를 띄웁니다.

## 7. 학습 과정과 결과

모든 수치는 같은 규칙의 자가대국 결과입니다. 별도 표기가 없으면 판이 끝날 때까지(또는 500,000점 상한까지) 둔 평균 점수입니다. 2코어 환경에서 돌렸습니다.

### 7-1. 평가식 가중치 학습 (CEM, `train3.js`)

CEM은 후보 가중치를 여러 개 뽑아 대국시키고, 상위 25%의 평균·분산으로 다음 세대를 뽑는 방식입니다.

| 단계 | 설정 | 추가 대국 | 결과 | 판단 |
|---|---|---|---|---|
| 1차 | 30세대 × 24후보 × 10판, 최대 80손 | 7,200 | 80손 평균 22,312 → 26,657 (40판) | 채택 |
| 2차 | 1차에서 이어서 20세대 × 16판, 최대 120손 | 7,680 | 판 끝까지 평균 36,662 (탐색 폭 4, 100판) | 채택 |
| 3차 | 배치 가능 위치 수(`fitCnt`, `minFit`) 추가, 판 끝까지 대국, 40세대 × 24후보 × 24판 | 23,040 | 탐색 폭 4: 36,662 → **49,892** (100판). 탐색 폭 24: 48,287 → **66,333** (20판, 최고 209,240) | 채택 |
| 4차 | 탐색 폭 8로 대국, 14세대 × 16후보 × 40판 | 8,960 | 탐색 폭 8: 62,587 → 61,647 (80판) | **기각**(개선 없음) |

2차 이후 진단에서는 죽기 직전 판에 9칸 찬 줄이 여러 개 쌓여 있었습니다. 세로 ㅣ로 한꺼번에 지우려다 그 구멍이 막혀 판이 차는 패턴이 반복돼, 3차에서 배치 가능 위치 수 항목을 추가했습니다. 4차에서 판 수를 늘려도 오르지 않아 "가중치 조정만으로는 한계"라고 판단하고 패턴표 학습으로 넘어갔습니다.

### 7-2. 패턴표 가치 함수 학습 (TD, `td2.js`)

학습 방식(TD(0)):
1. 한 조각씩, 가치 함수로 가장 좋은 위치에 둡니다(1수 탐욕).
2. 직전 판의 예측값을 "받은 점수 + 다음 판 예측값"에 가깝게 고칩니다.
3. 두 스레드가 같은 표를 공유 메모리로 함께 학습합니다.

같은 1수 탐욕 기준에서 기존 평가식만 쓰면 평균 약 19,800~22,600점이었습니다.

| 시도 | 내용 | 결과 | 원인과 대응 |
|---|---|---|---|
| 1 | 표와 평가식 계수를 함께 학습 | 계수가 발산(NaN), 평균 779 | 평가식 계수를 1로 고정, TD 오차를 ±200으로 제한 |
| 2 | 표만 단순 합산 갱신 | 평균 약 100점으로 붕괴 | 같은 패턴이 판 한 장에서 여러 번 조회돼 갱신이 수백 배로 증폭 → **정규화 LMS**(Σ중복수²로 나눔) 도입 |
| 3 | 정규화 LMS, 학습률 0.1 | 4분 만에 1수 탐욕 평균 35,727 | 학습은 되지만 점수가 주기적으로 무너졌다 회복하는 진동 |
| 4 | 학습률 0.03으로 이어서 | 38,945판 시점 저장본: 탐색 폭 4 **132,471**(20판, 기존 46,578), 탐색 폭 8 **169,729**(40판, 최고 500,084) | 이후 45,507판에서 다시 붕괴(평균 1,570) → 붕괴본 폐기 |
| 5 | 학습률 0.01, **최고 저장본 보관 + 붕괴 감지 시 자동 복구·학습률 절반** | 48,924판 저장본: 탐색 폭 24 **193,809**(10판, 최고 502,358) | 페이지 버전 3으로 배포 |
| 6 | 실제 추천 방식(3조각 빔 탐색)으로 두면서 학습 | 탐색 폭 4: 98,105 → 56,307 (30판) | **기각**. 상수항이 계속 커지며 표가 망가짐 |
| 7 | 6에서 손패를 다 쓴 판만 학습 | 탐색 폭 4: 42,610 (30판) | **기각** |
| 8 | 패턴표 확장(4×4, 2×5, 5×2 창 추가), 5의 저장본에서 이어서 학습률 0.03 | 77,608판 시점: 탐색 폭 8 **166,074**(같은 시드 180판, 기존 147,053, **+12.9%**) | 채택. 페이지 버전 4로 배포 |

붕괴 감지 기준과 학습 설정은 아래와 같습니다.

- **최고 저장본 갱신**: 최근 400판의 log(1000 + 점수) 평균이 기록을 넘으면 `td2_best.bin`에 저장합니다. 단순 평균은 소수의 고득점 판에 흔들려서 로그 평균을 씁니다.
- **붕괴 판정**: 그 값이 최고 기록보다 1.2 낮아지면(점수로 약 3.3배 하락) 최고 저장본으로 되돌리고 학습률을 절반으로 줄입니다.
- **저장 주기**: 2분마다 `td2.bin`에 저장합니다.
- **8번 시도의 중단**: 예정한 60분 중 19.5분에서 작업 환경 정리로 멈췄습니다.
- **채택한 표**: 학습 중 최고 저장본(71,679판)은 같은 시드 비교에서 152,063으로 오히려 낮아, 학습이 끝난 시점의 `td2.bin`을 채택했습니다.

## 9. 수정한 버그

- **추천 수순이 판에 일부만 보이던 문제**
  - 증상: 1번 추천을 눌렀는데 판에는 1번 조각만 놓인 것처럼 보이고 2·3번 조각이 보이지 않았습니다.
  - 원인: 1수째가 줄을 지우는 경우, 판이 "1수째 두기 직전" 단계 보기로 열리도록 해 둔 것이 원인이었습니다. 추천 계산은 3개를 모두 쓰고 있었습니다.
  - 수정:
    - 기본 보기를 전체 수순 표시로 바꿨습니다.
    - 수순 중 지워지는 줄을 노란 점선과 행 번호 취소선으로 표시합니다.
    - 지운 뒤 다시 채우는 칸은 사선으로 나눠 표시합니다.
    - 한 수씩 볼 때 이미 둔 수는 흐린 번호로 남깁니다.
- **입력을 바꾼 직후 화면 오류**: 조각을 바꾸는 순간 이전 추천 수순이 새 손패로 다시 그려지며 오류가 났습니다. 입력이 바뀌면 이전 추천 보기를 먼저 닫도록 수정했습니다.
- **조각 놓기 위치 보정**: 판 가장자리를 누르면 조각이 판 밖으로 나가 놓이지 않던 문제를 판 안쪽으로 당겨 놓도록 수정했습니다.

## 11. 폴더 구성과 실행 방법

```
index.html          빌드된 페이지 (이 파일만 열면 됨)
src/
  core.js           게임 규칙 엔진, 평가식, 빔 탐색 플래너, 시뮬레이터 (브라우저/Node 공용)
  ntv2.js           패턴표 가치 함수: 평가, 정규화 LMS 갱신, 페이지용 디코더
  app.html          페이지 템플릿 (UI, 웹 워커 탐색·롤아웃)
  build3.js         app.html + core.js + ntv2.js + 학습 데이터 → index.html
  weights3.json     평가식 가중치 (CEM 3차, 누적 37,920판)
  td2.bin           학습된 패턴표 (TD 누적 77,608판, float32)
  train3.js         평가식 가중치 학습 (CEM, 판 끝까지 대국)
  td2.js            패턴표 TD 학습 (2스레드 공유 메모리, 붕괴 자동 복구)
  benchV2.js        패턴표 모델 벤치마크
  bench3.js         평가식만 쓰는 모델 벤치마크
  rules_test.js     규칙 테스트
```

Node.js 18 이상, `src/` 폴더에서 실행합니다. 외부 패키지는 필요 없습니다.

```bash
node rules_test.js                                   # 규칙 테스트
node benchV2.js 90 8 9800000 td2.bin                 # 판 수, 탐색 폭, 시작 시드, 모델
node bench3.js 100 4 9000000 weights3.json           # 평가식만 쓰는 모델 벤치마크
node td2.js 60 0.01 td2.bin                          # 패턴표 이어서 60분 학습 (분, 학습률, 시작 모델)
node train3.js 40 24 24 weights3.json out.json 4     # 세대, 후보 수, 후보당 판 수, 시작 가중치, 출력, 탐색 폭
node build3.js td2.bin "페이지 하단 벤치 문구"       # ../index.html 다시 빌드
```

- `td2.js`는 `td2.bin`(현재)과 `td2_best.bin`(최고 기록)을 2분마다 저장하고, 진행 기록을 `td2.log`에 남깁니다.
- 학습한 표를 바꿨다면 `benchV2.js`로 기존 표와 **같은 시드**로 비교한 뒤 빌드하는 것을 권장합니다. 7-2의 8번처럼 최고 저장본이 실제로는 더 약할 수 있습니다.

### `td2.bin` 형식

```
[4바이트 헤더 길이][JSON 헤더 {games, L:[L0,L1,L2], sizes:[...]}][표1 float32 …][표2 …]…
```

페이지에 넣을 때는 표마다 int16으로 양자화(표별 배율 저장)하고 base64로 인코딩합니다. 그래서 4.5MB 모델이 페이지에서는 약 3MB가 됩니다.

## 12. 한계와 다음 단계

**한계**
- 조각 등장 확률이 추정값이라, 실제와 다르면 고단계(작은 조각이 줄어드는 구간)의 판단이 어긋날 수 있습니다.
- 능력 아이콘 생성 위치를 균등 무작위로 가정했습니다.
- 줄 제거 후 위 줄이 내려오는지는 공지로 확인되지 않았습니다(설정으로 전환 가능).

- 패턴표 학습을 수십만 판 이상으로 늘리기. 7-2의 8번 시도는 19.5분 만에 중단됐습니다.
