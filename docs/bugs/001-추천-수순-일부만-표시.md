# 버그 001: 추천 수순이 판에 일부만 보이던 문제

| 항목 | 내용 |
|---|---|
| 상태 | 수정됨 (커밋 `74c618c`에 포함. 이 커밋은 저장소 첫 업로드라 수정 전 코드는 이력에 없음) |
| 영향 범위 | 페이지 `index.html`의 추천 수순 표시. 추천 계산 자체는 영향 없음 |
| 관련 파일 | `src/app.html` |
| README | 9장 "수정한 버그" 1번 |

## 증상

"AI 추천 순위"에서 1번 추천을 누르면 판에 1번 조각만 놓인 것처럼 보이고, 2·3번 조각은 보이지 않았습니다. 사용자는 추천이 조각 하나만 쓰는 것으로 오해할 수 있었습니다.

## 원인

추천 계산은 손패 3개를 모두 쓰고 있었고, 표시 쪽이 문제였습니다.

- 수순을 고르면 판을 "몇 수째를 두기 직전" 단계 보기로 열도록 되어 있었습니다(시작 단계를 정하던 `defStep()`).
- 1수째가 줄을 지우는 수순이면 기본 단계가 "1수째 두기 직전"(`step = 0`)으로 잡혔습니다.
- 이 단계 보기는 그 수까지만 그리므로, 판에는 1수째만 보이고 2·3수째는 나타나지 않았습니다.
- 줄 제거 때문에 "전체 결과판"에서 1수째 조각이 지워져 보이는 혼란을 피하려던 설정이, 오히려 나머지 수를 가렸습니다.

## 수정

1. **기본 보기를 전체 수순 겹쳐 보기로 변경**
   - 수순을 고르면 항상 `recView.step = -1`(전체 보기)로 엽니다. `74c618c`에서는 `defStep()`이 항상 `-1`을 돌려주게 했고, 이후 페이지 개편(PR #1)에서 이 함수를 없애고 `-1`을 직접 넣습니다.
   - 원래 판 위에 모든 수를 번호로 겹쳐 그립니다(`simSteps(rec, -1)`).
2. **줄 제거 표시**
   - 수순 중 지워지는 줄은 칸에 노란 점선 테두리(`.cell.clr`)를, 행 번호에 취소선(`.ax.clr`)을 표시합니다.
3. **다시 채우는 칸 표시**
   - 줄이 지워진 뒤 다른 수가 다시 채우는 칸, 또는 원래 차 있던 칸에 겹치는 칸은 사선으로 나눠 표시합니다(`.cell.rec.reuse`).
   - 같은 칸에 여러 수가 겹치면 번호를 `1·3`처럼 함께 적습니다.
4. **한 수씩 보기 정리**
   - "다음 수 ▶"로 넘기면 그 수를 두기 직전 판을 보여 줍니다.
   - 이미 둔 수는 흐린 번호(`.cell.recold`)로 남겨, 앞 수와의 관계가 보이게 했습니다.

현재 코드 위치(`src/app.html`):
- `simSteps(rec, k)`: `k < 0`이면 전체 수순 번호와 지워지는 줄을 계산합니다.
- `render()`: `rec` / `recold` / `reuse` / `clr` 클래스를 붙입니다.
- 수순 선택과 계산 완료 시 `recView = { idx, step: -1 }`로 전체 보기를 엽니다.
- `#stepNext` / `#stepPrev`: 전체 보기 → 1수째 → … → 전체 보기 순서로 돌아갑니다.

## 확인

`src/ui_check_bug001.js`는 헤드리스 브라우저로 다음을 확인합니다.
- 모든 추천 후보를 차례로 눌렀을 때, 판에 그 수순의 모든 수 번호가 보이는지
- 기본 보기가 전체 수순 겹쳐 보기인지
- "다음 수 ▶"를 누르면 "1수째 두기 직전"으로 넘어가는지
